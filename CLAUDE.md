# Bloom Level-Up — notes for Claude

## This branch: `forge-1.20.1`

- A separate build of Bloom for **Forge 1.20.1** (Forge 47.x, ForgeGradle 6, Gradle 8.8, Java 17, official mappings). `main` stays the Fabric 26.3 mod: never merge this branch into main or the other way round; port changes across by hand.
- CI (`.github/workflows/build.yml` on this branch) runs `./gradlew build runGameTestServer`; same annotation trick as below for errors. The jar players install is the un-classified one in `build/libs` (MixinExtras inside, reobfuscated); `-slim` is the bare one.
- Ported in chunks. Files not ported yet stay where they are (unchanged 26.3 code, for reference) and are excluded in `build.gradle` (`notPortedYet`); a chunk ports its files and deletes their lines there.
- Forge stand-ins: profile = capability (`player/BloomAttachments`), packets = one `SimpleChannel` (`network/BloomNetwork`, client handlers in `client/ClientPackets`), data reload = `AddReloadListenerEvent`, attribute modifiers keyed by UUIDs made from Bloom ids (`StatEffects.ModifierId`). Data folders use 1.20.1 names (`tags/items`, `tags/blocks`, `tags/entity_types`, `loot_tables`, `structures`).
- Game tests: `src/gametest/java/**/gametest/forge/` (`@GameTestHolder`, template `bloomlevelup:empty`); the Fabric ones beside them are ported with their chunks.
- Client: drawing goes through `client/gui/BloomGraphics` (26.3-style calls on 1.20.1's `GuiGraphics`), so GUI code stays close to main's. Client mixins are in `bloomlevelup.forge.client.mixins.json`.
- Better Combat (1.9.0+1.20.1, optional): `compat/BetterCombat*` and `client/compat/BetterCombatClient*`; its swing is recognised by its attack damage modifiers. One mixin into Better Combat, for Batter Up!'s swings (`compat/mixin`, in its own `bloomlevelup.forge.bettercombat.mixins.json`, applied only when Better Combat is there). `-PwithBetterCombat` adds it, Player Animator and Cloth Config to the dev runs; CI's `build` and `client-test` jobs run once without and once with it (matrix `variant`).
- Forge pack: `pack/` is **Warionex** (named LegionWareX until 2026-10-30: ids, folders, data pack paths, the add-on's mod id, commands and log lines keep `legionwarex`; FreshOrangeSlices' medieval pack around Bloom; pack.json in cumulative `layers`, build_pack.py `--layers N`, boot_server.py, launch_test.py). CI's `pack` job (matrix `layers` 1-6) builds each layer, boots its server zip, starts a real Forge client (portablemc) to the title screen and into the server, then summons every modded entity once (mob check, `pack-mobs` annotation) and checks Bloom has sorted the pack's weapons, armor, daggers and bosses (from the server's `-Dbloomlevelup.dump` registry dump; `pack-bloom-unsorted`; the client's `-Dbloomlevelup.tooltips` dump has every weapon's tooltip, and both are kept in the `pack-screenshots-L<n>` artifacts); `pack-screenshots` prints what it saw (`shot-L<n>_bloom_pack_*`). GitHub keeps only 10 notices and 10 warnings per step, so the launch test's milestones (`pack-progress`) are printed by a step of their own. The full pack is the `warionex` artifact. Mod versions are pinned in `pack/pack.lock.json` (the last tested); `--update` shows newer ones, and the lock only moves after a test. pack.json's `skip_dependencies` leaves out a project a mod's Modrinth page lists as required but its jar doesn't need (Plasmo Voice, which Voiceless Survival lists beside Simple Voice Chat). Keep Bloom standalone: pack support goes in as optional tag entries or the pack's own config, never Bloom's defaults. Worldgen files it replaces (`worldgen`: the Overworld's erosion, for fewer mountains), recipes the pack takes out, items it removes (`removed_items`: their recipes and loot entries, found in the jars at build time), items it hides from JEI and its natural spawns (`spawns`: mods' biome modifiers off, biome tags, its own forge:add_spawns groups, quiet biomes, respaced structure sets, structure spawns; biome lists stay in the Overworld unless they name `dimensions`) go in `pack_data` (pack.json), a data pack Open Loader loads into every world; the pack test checks it (`pack-data`, `pack-spawns`: each overworld biome's modded share in mobs, from the dump's biome rows). The server dump also has every biome's spawn list and every structure's own spawns; the pack artifact keeps the server's generated `config/` and `world/serverconfig/`. Resource packs, the shader, key bindings and single settings in other mods' client config files come from pack.json's `client_presets` (`keys`, `settings`, `patches`, `copies`, whole files in `pack/files/`), applied by Bloom's `config/PackDefaults` before the game or any mod reads its settings (`client/PackDefaultsEarly`, Forge reads options before mods load), each part once per change of it; the pack test checks them after a real client run. The quest book (FTB Quests) is written as JSON in `pack/quests/` (one file per chapter, the format at the top of `pack/quest_book.py`), built into `config/ftbquests/quests/` per layer with only what the layer's mods have (guide chapters are flexible: their dependency lines suggest an order, nothing locks); the pack test checks it loads and that every id it names is in the game (`quest book` notes), and screenshots it (`pack_quests`).
- Warionex add-on: `addon/` is its own small Forge 1.20.1 mod (mod id `legionwarex`, not part of Bloom; its own Gradle build, run with the repo's wrapper: `./gradlew -p addon build runGameTestServer`). It reaches other mods without compiling against them (entity tags, saved data, fields read by name), and its game tests run with Migamigos (+ GeckoLib, Framework), Illager Invasion (+ Puzzles Lib) and Bosses'Rise in the dev run. CI's `addon` job builds and tests it; the pack jobs pack its jar in like Bloom (build_pack.py `--extra-jar`). So far: Migamigos companions' keepsakes (a fallen befriended one comes back after a day) and wild companions despawning like monsters; daytime illager war bands and coastal pirate bands (`band/`, `/legionwarex band war|pirate [size]`, which the pack test calls and screenshots: `shot-L6_bloom_pack_band_*`; band pirates are led by a rook and quicker than the Kraken's crew, `band/PirateTuning`); pirate charts that lead to an unbeaten boss lair no earlier chart has shown (the least-charted boss first, then the nearest), as a treasure map (Overworld only; `chart/`, beaten bosses, charted lairs and charts per boss kept with the world in `BeatenBosses`, the lair list in `data/legionwarex/legionwarex/lairs/*.json`, `/legionwarex chart find|lairs|beaten|forget|probe <structure>`; the pack test checks the lair list, and the boot test reads three charts in the shipped world, since the client test's world is flat with structures off: `server-chart`); lone daytime sentinels and pillager scouts (`sentinel/`, the table in `data/legionwarex/legionwarex/sentinels/*.json`, `/legionwarex sentinel [<entity>|all|check]`, which the pack test calls: `pack-sentinels`, `shot-L6_bloom_pack_sentinels`); Born in Chaos's pumpkin folk (the Harvest Court) all year (`harvest/`: a `MobSpawnEvent.SpawnPlacementCheck` that says yes outside its 25 October to 7 November window on the same terms otherwise; their weights are pack_data's `harvest_court` group; `/legionwarex harvest`, which the pack test runs at midnight and at noon); a new world's spawn on the mainland (`world/MainlandSpawn`); mobs killed by other mobs (golems, rivals) drop nothing unless a player, their pet or companion hit them (`world/MobKillDrops`, game tests in `DropsGameTests`); no endless buffs on zombies (`world/ZombieBuffs`: a good effect over an hour long is refused, or taken off when a saved zombie loads; the first refusal from each place in the code is logged as "LegionWareX buffs:" with its calls; `ZombieBuffsGameTests`); a terrain survey (`-Dlegionwarex.terrain=<file>`: the pack's Overworld beside vanilla's for the same seed, and where spawns land; the pack test's `pack-terrain` annotations).
- CI's `client-test` job boots a real client on a virtual display (`gametest/forge/client/ClientSmokeTest`, on when `BLOOM_CLIENT_TEST` is set) and screenshots the hub; the `screenshots` jobs print each picture as annotations (`shot-<name>-NN`, base64 JPEG) to rebuild from the checks API.

## Shared notes (written for main)

- Fabric mod, MC 26.3, Java 25, Mojang official names (no mappings). Versions in `gradle.properties` come from the official Fabric template.
- The sandbox cannot reach Fabric/Mojang maven, so `./gradlew build` only runs in GitHub Actions. Verify by pushing and reading the run. Job logs are not reachable from the sandbox; on failure the build workflow attaches compile/test errors as annotations (`build-errors-NN`), read via `GET /repos/FreshOrangeSlices/BloomLevel-Up/check-runs/<job id>/annotations`.
- 26.3 renamed much of the client API (`GuiGraphicsExtractor`, `extractRenderState`, `setScreenAndShow`, ...). Look up exact signatures rather than guessing: the javap API-dump tool was removed from the tree but lives in git history (`git show c987f4a:tools/api-dump/README.md`); run it from a throwaway `ci/api-dump*` branch, never main. Fabric API's own source (branch `26.3`) is also a good reference.
- The pure-Java core (`definition/`, `config/BloomConfig`, `player/{BloomProfile,CategoryProgress,OwnedMajor}`, `progression/`, `stats/`) must not import Minecraft classes, so it can be compiled and unit-tested locally with plain `javac` (Java 21 locally: avoid Java 22+ syntax there).
- Design docs in `docs/design/` are the source of truth; record any choice the docs leave open in `docs/DECISIONS.md`.
- Server is authoritative; client only renders synced state. All profile changes go through `ProgressionService`.
- New game hooks are registered from `registry/BloomRegistries`.
- The user works in chunks: finish one chunk, push, report, then wait.
